System Monitor: опис проєкту
Що це за проєкт

System Monitor це система моніторингу комп'ютера. Вона збирає основні показники роботи системи (завантаження процесора, оперативної пам'яті, диска, температуру процесора та мережеву активність), зберігає їх у базі даних PostgreSQL і показує у зручному вікні з графіком, сповіщеннями та прогнозом навантаження.

З яких частин складається система

Проєкт має чотири основні частини, які працюють разом.

Агент (файл agent.py) це програма, яка безпосередньо знімає показники з комп'ютера. Для завантаження процесора, пам'яті, диска та мережі він використовує бібліотеку psutil. Температуру процесора він отримує від програми LibreHardwareMonitor через її локальний вебсервер. Агент не збирає дані постійно: він чекає, поки сервер не передасть команду почати збір, після чого робить десять вимірювань із паузою приблизно п'ять секунд і надсилає їх на сервер.

Сервер (файл server.py) побудований на FastAPI. Він приймає дані від агента й записує їх у базу, віддає їх дашборду, а також керує завданнями на збір: пам'ятає, чи збір очікує, виконується або вже завершений. Крім того, сервер вміє формувати сповіщення за порогами навантаження та температури.

База даних PostgreSQL зберігає зібрані вимірювання та список відомих пристроїв. Вона складається з двох таблиць: у першій перелічені пристрої, у другій лежать самі показники з прив'язкою до пристрою і часу.

Дашборд (файл dashboard.html) це інтерфейс користувача. Він відкривається у вікні програми й показує чотири картки з поточними значеннями, графік історії навантаження, список сповіщень, статус системи та прогноз. Графік будується за допомогою бібліотеки Chart.js.

Усе це об'єднує лаунчер (файл laucher.py). Він запускає сервер і агента всередині одного процесу, чекає, поки сервер буде готовий, а потім відкриває вікно з дашбордом за допомогою pywebview. Саме лаунчер перетворюється на готовий файл SystemMonitor.exe.

Як відбувається збір даних

Користувач відкриває програму, обирає свій пристрій у лівій панелі та натискає кнопку «Дістати дані». Дашборд надсилає серверу команду на збір, і сервер видаляє старі дані цього пристрою та створює нове завдання. Агент регулярно запитує в сервера, чи є для нього завдання, і щойно воно з'являється, починає знімати показники. Після кожного вимірювання він відправляє результат на сервер. Дашборд у цей час кожні кілька секунд перевіряє, як просувається збір. Коли десять вимірювань отримано, завдання вважається завершеним, і дашборд завантажує нові дані та оновлює картки, графік і сповіщення.

Прогноз навантаження

Після завершення збору можна натиснути кнопку «Прогноз». Він показує очікуване навантаження процесора через одну, три та п'ять хвилин. Розрахунок виконується прямо в браузері методом лінійної регресії за десятьма зібраними точками. Оскільки ці точки охоплюють лише близько хвилини, чим далі горизонт прогнозу, тим більше результат наближається до середнього значення навантаження, щоб не отримувати нереалістичних цифр. Тому прогноз слід сприймати як орієнтовний.

Сповіщення

Система позначає небезпечні значення. Навантаження процесора та пам'яті вважається підвищеним приблизно від 75-80 відсотків і критичним від 90. Для диска критичним вважається заповнення понад 90 відсотків. Температура процесора вважається підвищеною від 70 градусів і критичною від 85.

Що потрібно для роботи

Для роботи потрібні Windows, встановлена база PostgreSQL з базою даних monitor_db та програма LibreHardwareMonitor. Її потрібно запускати від імені адміністратора та вмикати в налаштуваннях пункт Remote Web Server, інакше температура процесора в системі показуватиметься як нуль. Решта показників працює й без неї.

Параметри підключення до бази (адреса, порт, користувач, пароль і назва бази) програма бере з файлу .env, а якщо його немає, використовує значення за замовчуванням. Цей файл містить пароль, тому його не можна публікувати на GitHub.
Як запустити

Із вихідного коду програма запускається через файл лаунчера. Для звичайного користування можна зібрати її в один файл SystemMonitor.exe за допомогою PyInstaller. Під час збірки дашборд упаковується всередину exe, тому після будь-яких змін у ньому програму потрібно збирати заново.
Бібліотеки Python

Серверна частина

FastAPI - фреймворк для створення вебсервера та REST API. Через нього агент надсилає дані, а дашборд їх отримує. Також він автоматично перевіряє формат вхідних даних.
Pydantic - встановлюється разом із FastAPI. Описує структуру даних телеметрії (клас TelemetryIn) і перевіряє, що значення мають правильні типи.
Uvicorn - вебсервер, який запускає застосунок FastAPI. У проєкті він працює всередині лаунчера в окремому потоці.
SQLAlchemy - бібліотека для роботи з базою даних. Через неї сервер виконує SQL-запити (запис і читання телеметрії, реєстрація пристроїв).
psycopg2 (psycopg2-binary) - драйвер, який дає SQLAlchemy змогу підключатися саме до PostgreSQL.
python-dotenv - читає параметри підключення до бази (адреса, користувач, пароль) із файлу .env.

Агент

psutil - збирає системні показники: завантаження процесора, використання оперативної пам'яті, заповнення диска, мережевий трафік.
requests - HTTP-клієнт. Агент використовує його, щоб опитувати сервер, відправляти телеметрію та отримувати температуру з LibreHardwareMonitor.
socket, datetime, time - стандартні модулі Python для отримання імені комп'ютера (використовується як ідентифікатор пристрою), позначок часу та пауз між вимірюваннями.

Лаунчер і вікно програми

pywebview - відкриває HTML-дашборд у окремому віконці, як у звичайній програмі, без браузера.
threading - запускає сервер і агента паралельно в одному процесі.
urllib.request - стандартний модуль, яким лаунчер перевіряє, чи сервер уже готовий (запит на /health).
os, sys - робота зі шляхами до файлів, зокрема коли програма запакована в exe.

Збірка

PyInstaller - пакує весь проєкт в один файл SystemMonitor.exe, який можна запускати без встановленого Python.
Бібліотеки та інструменти інтерфейсу
Chart.js - малює графік історії навантаження (CPU, RAM, диск, температура). Лежить у проєкті як локальний файл chart.umd.min.js, тому працює без інтернету.
Fetch API - вбудований засіб браузера, яким дашборд звертається до сервера.
Прогноз навантаження написаний власноруч на JavaScript (метод лінійної регресії), без сторонніх бібліотек.
Зовнішні програми
PostgreSQL - система керування базами даних, у якій зберігаються всі виміри.
LibreHardwareMonitor - програма, що читає датчики температури. Агент отримує від неї дані через вбудований вебсервер (порт 8085).
